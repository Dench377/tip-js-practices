## 4. Модель данных и функции

### Описание модели задачи:
Каждая задача представляет собой плоский объект:
```js
{
  id: 20,
  title: "Подготовить демонстрацию",
  completed: false,
  priority: "medium" // "low" | "medium" | "high"
}
```

### Правила валидации:
- `id`: положительное безопасное целое число (`Number.isSafeInteger(id) && id > 0`).
- `title`: непустая строка длиной от 1 до 100 символов после обрезки краевых пробелов методом `.trim()`.
- `completed`: строго логический тип (`boolean`), при создании всегда `false`.
- `priority`: строго одно из трех значений `"low"`, `"medium"`, `"high"`.

### Контракт функций:
- Операции создания и изменения (`createTask`, `addTask`, `setTaskCompleted`, `renameTask`, `removeTask`) возвращают стандартизированный объект результата:
  - При успехе: `{ ok: true, task: <объект> }` или `{ ok: true, tasks: <новый массив> }`.
  - При ошибке: `{ ok: false, error: "<понятное сообщение>" }`.
- Операции чтения (`findTaskById`, `getPendingTasks`, `getTaskTitles`, `getTaskStats`) возвращают запрошенные структуры данных напрямую либо `undefined` (при ненахождении записи).

### Ответы на теоретические вопросы:
- **Почему `id` не равен индексу:** Индекс отражает физическую позицию элемента в массиве и непрерывно сдвигается при фильтрации, сортировке или удалении соседних записей. `id` — это неизменный уникальный бизнес-идентификатор сущности.
- **Почему `getTaskStats` возвращает число, а не строку с процентом:** Прогресс в модели данных возвращается точным числом с плавающей точкой, чтобы функцию можно было использовать для дальнейших расчетов, проверок и тестов. Округление `.toFixed(1)` возвращает строку и выполняется только на слое вывода.
- **Какие объекты копируются при изменении задачи:** Создается новый массив (`tasks.map(...)` или `tasks.filter(...)`) и новый объект только для той задачи, которая непосредственно изменяется (`{ ...item, completed }`). Все остальные нетронутые задачи повторно используются по существующим ссылкам без дублирования памяти.

## 9. Ответы на контрольные вопросы

1. **Чем параметр отличается от аргумента, а `return` — от `console.log()`?**  
   Параметр — это переменная в объявлении функции; аргумент — это конкретное значение, передаваемое при ее вызове. Оператор `return` возвращает вычисленное значение вызывающему коду в память программы для дальнейшей обработки. `console.log()` лишь выводит текстовое сообщение в поток вывода терминала и не возвращает полезных данных (`undefined`).

2. **Почему стрелочная функция с фигурными скобками может вернуть `undefined`, хотя внутри записано вычисление?**  
   В стрелочной функции краткий автоматический возврат работает только без фигурных скобок (`x => x * 2`). Если тело заключено в фигурные скобки `{}`, оно считается блоком инструкций, и для возврата значения строго необходим явный оператор `return`. Без него функция возвращает `undefined`.

3. **Для каких аргументов применяется значение параметра по умолчанию?**  
   Значение параметра по умолчанию применяется только в том случае, если аргумент не был передан вообще либо передан явно со значением `undefined`. Для значений `null`, `0`, `false`, `""` значение по умолчанию не активируется.

4. **Что запрещает `const`, если переменная хранит объект?**  
   `const` запрещает повторное связывание (переприсваивание) самой переменной другому объекту через оператор `=`. При этом внутренние свойства объекта остаются полностью изменяемыми.

5. **Почему два объекта с одинаковыми полями могут не быть равны при `===`?**  
   В JavaScript объекты являются ссылочными типами данных и при операторе `===` сравниваются по идентичности ссылок в оперативной памяти, а не по содержимому. Два разных объекта, размещенных по разным адресам памяти, всегда дадут `false`.

6. **Чем копирование массива через spread отличается от копирования каждого объекта внутри него?**  
   Копирование через spread (`[...tasks]`) является поверхностным (shallow copy): создается новый массив-контейнер, но элементами остаются те же самые ссылки на исходные объекты. Для независимого копирования объектов необходимо дополнительно копировать каждый объект (`{ ...task }`).

7. **Чем различаются результаты `find`, `filter` и `map`? Что произойдёт, если внутри callback изменить свойство исходной записи?**  
   - `find`: возвращает первую совпавшую ссылку на объект либо `undefined`.
   - `filter`: возвращает новый массив, содержащий отобранные по условию элементы.
   - `map`: возвращает новый массив той же длины с результатами преобразования каждого элемента.  
   Если внутри callback изменить свойство объекта (`item.title = ...`), исходный объект в памяти будет безвозвратно мутирован, нарушая чистоту функций.

8. **Почему идентификатор задачи нельзя использовать как индекс массива?**  
   Индекс массива — это порядковый номер позиции от 0 до length-1, который изменяется при удалении или вставке элементов. `id` — постоянный неизменяемый ключ сущности, который может быть разреженным, начинаться с больших чисел (например, 203) и не совпадает со смещением в массиве.

9. **Где проверяется уникальность `id`: в `createTask` или `addTask`, и почему?**  
   Уникальность `id` проверяется исключительно в `addTask`, так как функция `createTask` отвечает только за валидацию единичной записи и не имеет доступа к текущему списку всех существующих задач.

10. **Почему `"false"` не принимается как значение поля `completed`?**  
    В JavaScript строка `"false"` является непустой строкой, которая при неявном приведении к boolean дает значение `true`. Во избежание логических ошибок контракт требует строгого типа `boolean` (`typeof completed === "boolean"`).

11. **Какие объекты нужно создать заново при изменении одной задачи? Какие разрешается использовать повторно?**  
    Заново создаются новый массив-контейнер и новый объект изменяемой задачи (`{ ...task, completed }`). Все остальные нетронутые объекты задач разрешается повторно использовать по ссылкам.

12. **Почему одного сравнения ссылок на старый и новый массив недостаточно для проверки отсутствия мутации?**  
    Создание нового массива `[...tasks]` меняет ссылку на массив (`old !== new`), однако свойства объектов внутри него могли быть напрямую мутированы. Необходимо дополнительно проверять неизменность самих объектов и их свойств.

13. **Почему процент возвращается числом, а округляется только при выводе?**  
    Модель данных должна предоставлять точные числовые значения без потери точности для корректных математических операций и фильтраций. Метод `.toFixed(1)` возвращает строку и относится исключительно к уровню пользовательского интерфейса/отображения.

14. **Чем различаются ожидаемый отказ операции и ошибка в самой программе?**  
    Ожидаемый отказ (валидация некорректных входных данных) — это нормальная ветвь бизнес-логики, возвращающая объект результата `{ ok: false, error }` без аварийного завершения. Ошибка в программе (исключение, bug) приводит к генерации `Error` и краху процесса.

15. **Что дают отдельный `package.json`, `import` и `export`? Почему `task-service.js` не должен импортировать `demoTasks`?**  
    `package.json` включает нативную модульность ECMAScript (`"type": "module"`). `export` и `import` обеспечивают модульную изоляцию и явные зависимости. Сервисный модуль `task-service.js` не должен зависеть от конкретных данных (`demoTasks`), оставаясь чистым переиспользуемым сервисом, принимающим массив аргументом.

16. **Что потребуется изменить для использования подготовленной логики из браузерного интерфейса, а что можно сохранить?**  
    Всю сервисную логику `task-service.js` можно сохранить без малейших изменений на 100%. Изменится только файл `main.js`: вместо консольного вывода `console.log` он будет рендерить HTML-разметку в DOM-дерево браузера и подписываться на события кликов и отправки форм.
